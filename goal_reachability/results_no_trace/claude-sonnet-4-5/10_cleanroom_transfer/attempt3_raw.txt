**FAILING QUERY 1: `A[] (courier.CleanRoom imply sterile_ready)`**

This means: whenever the courier is in CleanRoom, sterile_ready must be true.

Looking at the model:
- CourierBot starts in Idle (urgent), immediately transitions to CleanRoom with `y = 0`
- SterilizerBot starts in Idle (urgent), immediately transitions to Sterilize with `x = 0`
- sterile_ready is set to true only when SterilizerBot transitions from Sterilize to Airlock (after x >= 3)

The problem: Both processes have urgent initial locations, so they both fire their first transitions immediately at time 0. CourierBot can reach CleanRoom before SterilizerBot has set sterile_ready = true. There's no guard preventing this race.

Fix: The CourierBot's transition from Idle to CleanRoom must wait for sterile_ready to be true. Add guard `sterile_ready` on that transition.

**FAILING QUERY 2: `A[] not (sterilizer.Airlock && courier.Airlock)`**

This means: sterilizer and courier must never both be in Airlock simultaneously.

Looking at the model:
- SterilizerBot sets `airlock_reserved = true` when entering Airlock
- SterilizerBot sets `airlock_reserved = false` when leaving Airlock
- CourierBot's transition to Airlock has no guard checking airlock_reserved

The problem: CourierBot can enter Airlock even when airlock_reserved is true (i.e., when SterilizerBot is already in Airlock).

Fix: The CourierBot's transition from CleanRoom to Airlock must guard on `!airlock_reserved`.

- `E<> sterilizer.Done`: Still reachable (sterilizer proceeds independently)
- `E<> courier.Done`: Still reachable (courier waits for sterile_ready, then waits for airlock to be free, then proceeds)
