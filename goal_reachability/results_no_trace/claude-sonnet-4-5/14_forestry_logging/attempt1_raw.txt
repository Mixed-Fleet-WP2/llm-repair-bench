**FAILING QUERY 1: `A[] not (feller.CutTree && hauler.CutZone)`**

This query requires that the feller is never in `CutTree` while the hauler is in `CutZone` simultaneously.

Looking at the model:
- `feller` goes from `Idle` → `CutTree` (setting `cutting_zone_busy = true`)
- `hauler` goes from `Idle` → `CutZone` after 1 time unit
- Both processes start in urgent locations and immediately transition

The problem: There's no guard preventing `hauler` from entering `CutZone` when the feller is already in `CutTree`. The `cutting_zone_busy` flag is set by the feller but never checked by the hauler.

The fix: Add a guard `!cutting_zone_busy` on the transition from `hauler.Idle` to `hauler.CutZone`.

**FAILING QUERY 2: `feller.TreeFelled --> hauler.Collect`**

This is a leads-to property: whenever feller reaches `TreeFelled`, hauler must eventually reach `Collect`.

Looking at the model:
- When feller completes cutting (reaches `TreeFelled`), it sets `tree_felled = true`
- Hauler at `Decision` checks `tree_felled` to go to `Collect`
- BUT: The hauler might already be at `Decision` with `tree_felled = false`, take the else-branch to `Wait`, and then loop between `Wait` and `Decision` forever if it keeps arriving at `Decision` while `tree_felled` is still false

Wait, let me reconsider the timing:
- Feller takes 3-5 time units in `CutTree`
- Hauler takes 1-2 time units in `CutZone`, then goes to `Decision`
- At `Decision`, if `tree_felled` is false, hauler goes to `Wait` for 1-2 time units, then back to `Decision`

The issue is that there's an unconditional edge from `Decision` to `Wait` (the else-branch when `tree_felled` is false). This creates a loop where hauler can cycle between `Decision` and `Wait` indefinitely if the tree is never felled.

But actually, the feller WILL fell the tree eventually (Query 3 `E<> feller.TreeFelled` passes, implying it's reachable). So the real issue is likely that the hauler never reaches `Decision` after the tree is felled, OR the hauler gets stuck somewhere.

Actually, looking more carefully: The transition from `Decision` to `Wait` has NO guard - it's always enabled. In UPPAAL, when multiple transitions from a location are enabled, the system can non-deterministically choose any of them. So even if `tree_felled` is true, the hauler might still take the transition to `Wait` instead of to `Collect`.

The fix: Add guard `!tree_felled` to the transition from `Decision` to `Wait`.
