**FAILING QUERY 1: `A[] (amr.EnterAisle imply aisle_clear)`**

The query requires that whenever the AMR is in location `EnterAisle`, the global variable `aisle_clear` must be true.

Analyzing the model:
- AMR transitions from `Idle` to `EnterAisle` unconditionally (no guard)
- Scanner sets `aisle_clear = true` only when transitioning from `VerifyShelf` to `ShelfVerified` (after x >= 2)
- Both processes start in `Idle` locations marked urgent
- AMR can reach `EnterAisle` before Scanner completes verification

The race condition: AMR can enter `EnterAisle` before `aisle_clear` is set to true by the scanner. The fix is to add a guard on AMR's transition to `EnterAisle` requiring `aisle_clear` to be true.

**FAILING QUERY 2: `scanner.ShelfVerified --> amr.Restock`**

The leadsto operator `-->` means: whenever `scanner.ShelfVerified` is reached, `amr.Restock` must eventually be reached.

Analyzing the model:
- AMR reaches `Decision` (urgent), then can either:
  - Go to `Restock` if `shelf_verified` is true
  - Go to `Replan` unconditionally (no guard)
- From `Replan`, AMR can loop back to `Decision`
- The issue: at `Decision`, the transition to `Replan` has no guard, so it can fire even when `shelf_verified` is true, allowing the AMR to loop forever in the `Decision`-`Replan` cycle instead of going to `Restock`

The fix: The transition from `Decision` to `Replan` should only be taken when `shelf_verified` is false (i.e., when the shelf is not verified). Add guard `!shelf_verified` to the `Decision` to `Replan` transition.
