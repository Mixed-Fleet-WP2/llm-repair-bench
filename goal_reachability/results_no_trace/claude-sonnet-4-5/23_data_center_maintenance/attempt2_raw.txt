**FAILING QUERY 1: `A[] (service.OpenRack imply rack_safe)`**

This means: whenever ServiceRobot is in location OpenRack, rack_safe must be true.

Looking at the model:
- ServiceRobot transitions from Idle → OpenRack (with y=0 assignment)
- OpenRack has invariant y ≤ 2
- ThermalInspector transitions from Idle → ThermalScan (with x=0) → RackCleared
- rack_safe is set to true on the transition ThermalScan → RackCleared (when x ≥ 2)

The problem: Both processes start independently. ServiceRobot can reach OpenRack immediately (urgent Idle location), while ThermalInspector needs at least 2 time units (x ≥ 2 guard) before setting rack_safe = true. Therefore, service.OpenRack can be reached while rack_safe is still false.

**Fix for Query 1:** The transition from ServiceRobot Idle → OpenRack needs to guard on rack_safe being true.

The real issue: ServiceRobot can reach Decision before rack_safe is true, take the unlabeled transition to Wait, and then loop Wait ↔ Decision forever without ever taking the rack_safe guarded transition to ReplaceUnit, even after rack_safe becomes true later, because once in the Wait ↔ Decision loop, there's no escape.

Actually no - from Decision, if rack_safe is true, it SHOULD take that transition. But Decision is urgent, so it must take AN enabled transition immediately. **Fix for Query 2:** The Decision → Wait transition should be guarded with !rack_safe, so that when rack_safe is true, only the ReplaceUnit path is enabled.
