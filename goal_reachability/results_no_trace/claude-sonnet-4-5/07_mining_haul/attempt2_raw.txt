## FAILING QUERY 1: `A[] not (drill.Drill && hauler.Tunnel)`

**Analysis:**
- This query requires that drill.Drill and hauler.Tunnel never overlap
- Currently, both processes start from urgent locations (Idle) and transition independently
- DrillBot: Idle → Drill (sets drilling_active = true)
- HaulerBot: Idle → Tunnel
- Since both Idle locations are urgent and have no guards, both processes can fire simultaneously on initialization
- The drill.Drill location has invariant `x <= 5` and exits at `x >= 3`
- The hauler.Tunnel location has invariant `y <= 2` and exits at `y >= 1`
- There's clearly an overlap window: both can be active simultaneously

**Root cause:** HaulerBot's transition from Idle → Tunnel has no guard preventing it from entering Tunnel while drilling is active.

**Fix:** Add guard `!drilling_active` on the HaulerBot Idle → Tunnel transition to prevent overlap.

## FAILING QUERY 2: `A[] (hauler.Transport imply load_weight <= MAX_LOAD)`

**Analysis:**
- MAX_LOAD = 10
- HaulerBot sets `load_weight = 12` on transition Tunnel → Loading
- Then it transitions Loading → Transport (where the query checks the invariant)
- At Transport, load_weight is still 12, which violates `<= 10`

**Root cause:** The assignment `load_weight = 12` on Tunnel → Loading exceeds MAX_LOAD.

**Fix:** Change the assignment to respect MAX_LOAD. The assignment should be `load_weight = 10` (or any value ≤ MAX_LOAD). Since the model likely intends to test proper loading, I'll use a valid load value.
