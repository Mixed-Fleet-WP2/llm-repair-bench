# missions_goal_reachability

Same 30 missions as `missions/`, extended with **goal-reachability queries**
that check a repair did not satisfy the original properties vacuously — e.g. by
time-locking the model so the unsafe state (and everything else) becomes
unreachable. Generated by `../make_goal_dataset.py`; do not edit by hand.

## Goal queries

For each mission, the goal locations are the sink locations (no outgoing edge)
of each robot in `faulty.xml` — one per robot in all 30 missions. One query per
robot is added:

```
E<> drone.Done                    # each robot can still reach its goal
E<> crane.Done
```

A joint query `E<> (drone.Done && crane.Done)` is available with
`make_goal_dataset.py --joint` but is off by default: it also rejects correct
repairs that add a location after a robot's goal (the robot finishes, then
moves on), e.g. deepseek-reasoner's repairs of missions 05 and 09.

Every goal query is verified with `verifyta` to be **satisfied on the faulty
model**, so the goal is reachable before repair. A repair that makes any of
them fail has broken the mission, even if the original properties now pass.

## Files per mission

| File | Contents |
|---|---|
| `faulty.xml` | original model, goal queries appended to `<queries>` |
| `queries.q` | original queries followed by the goal queries |
| `goal_queries.q` | goal queries only |
| `metadata.json` | original metadata plus a `goal_reachability` section |

## Usage

Audit an existing repair:

```bash
verifyta -q results/gpt-5.1/08_construction_lift/repaired.xml \
         with_reachability/missions_goal_reachability/08_construction_lift/goal_queries.q
```

Or run the benchmark on this dataset (`../run_no_trace.sh`): the goal queries pass initially, so the
existing regression check rejects any attempt that makes a goal unreachable.
Note the goal queries are then visible to the LLM in the model's `<queries>`
block, which changes the task compared to `missions/`.

## Limitations

- Sink locations stand in for "mission goal"; there is no ground-truth
  intended repair in the dataset.
- Reachability is necessary, not sufficient: a repair can keep the goal
  reachable and still differ from the intended fix.
